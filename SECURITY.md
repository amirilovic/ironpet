# Security

ironpet runs on your Mac with your user's permissions, watches your coding agents, and can start agents that edit files and run commands. This page lists what it touches and what protects it, so you can decide what to turn on. Nothing outside `~/.ironpet` is changed until you confirm the welcome window on first launch.

## Reporting a vulnerability

Please use GitHub's **Report a vulnerability** button on the repository's Security tab instead of a public issue. You'll get a reply within a week.

## What runs where

- **Local HTTP server.** The app listens on `127.0.0.1` only (port written to `~/.ironpet/port`). Every request has to carry the random 256-bit token in `~/.ironpet/token` (mode `0600`), or it gets a 403. The `/test/*` endpoints exist only when the app is started with `--test-mode`.
- **Hooks.** `~/.ironpet/bin/ironpet-hook` is called by the agents you choose to watch (Cursor, Claude Code, Codex, Gemini CLI, GitHub Copilot and Pi), so ironpet can show sessions you started yourself. The welcome window and Settings list only agents found on this Mac, and each is off until you turn it on. Hooks only report status: short timeouts, always exit 0, never block or fail your agents. They no longer approve anything. A chat that ironpet runs sets `IRONPET_ACP_RUN=1` on the agent, and the hook script skips those runs.
- **Agents over ACP.** Chat talks to the agent over the [Agent Client Protocol](https://agentclientprotocol.com) (JSON-RPC on the agent's stdin and stdout). ironpet starts the agent you pick from your own install, found through your login shell's `PATH`: `cursor-agent acp`, `gemini --acp`, `opencode acp` and so on. Claude Code, Codex and Pi have no ACP mode of their own, so ironpet runs a small adapter (a single `.mjs` file in `IronPet.app/Contents/Resources/acp/`) on your Node 22 or newer. The adapter drives your installed `claude`, `codex` or `pi`, which ironpet passes in `CLAUDE_CODE_EXECUTABLE`, `CODEX_PATH` or `PI_ACP_PI_COMMAND`. The app bundle contains no agent and no JavaScript runtime. ironpet declares no `fs` or `terminal` client capability, so agents read and write files and run commands with their own tools, under their own permission settings. It lists an agent in the picker only when its command exists and, for agents with native ACP, answers `initialize` (ironpet starts each one briefly to check).
- **Approvals.** The agent decides when to ask. When it wants to run a tool it may send `session/request_permission`, and ironpet either answers or shows an Allow / Deny card. File edits, deletions and shell commands ask. Reads, searches, web fetches and read-only MCP tools (names starting with `get`, `list`, `search` and similar) are allowed without a card. The per-chat **Auto** switch skips the cards for that chat only. The agent stays in its normal asking mode and ironpet answers for it. Even with Auto on, commands that match a destructive pattern (`rm -rf`, `git push --force`, `git reset --hard`, `git clean -f`, `DROP TABLE`, `mkfs`, `dd if=`, …) still ask. Auto resets with each new chat and when you open a chat from history. It is remembered only for the chat that was open when the app quit, so a restart doesn't silently turn it off mid-task. Writes to ironpet's own memory notes (`~/.ironpet/memory`) don't ask, and neither do ironpet's own task tools on its `ironpet` MCP server (`tasks_list`, `tasks_get`, `tasks_create`, `tasks_update`, `tasks_close`); `tasks_delete` asks. A request that ironpet cannot show (the app quit, or the turn was stopped) is answered with a cancel, and an unanswered card waits until you decide or stop the turn.
- **Approval cards depend on the agent.** ironpet cannot force an agent to send `session/request_permission`. An agent that runs a tool without asking, because of its own settings, an allow-list or a "never ask" mode, does so without any card, and ironpet only sees the tool call afterwards. For example, `cursor-agent acp` runs commands on its own allow-list (such as `ls`) without asking and asks for the rest. Check an agent's own permission settings before you rely on the cards. The destructive-command check applies only to requests the agent sends.
- **One download, only when you allow it.** If you pick Claude Code, Codex or Pi and your PATH has no Node 22 or newer, the chat shows a **Download Bun** button instead of failing. Only a click starts the download. ironpet fetches Bun 1.4.4 (about 40 MB) from `github.com/oven-sh/bun`, reads the expected SHA-256 from the same release's `SHASUMS256.txt`, and unpacks the archive only if the checksum matches. It then clears the macOS quarantine flag on that file and keeps it at `~/.ironpet/runtime/bun`. A mismatch or a failed download shows an error and runs nothing. This is the only network request ironpet makes on its own initiative besides the optional GitHub, Sentry and voice features below.
- **Telegram (off by default).** With Chat from Telegram on, ironpet long-polls `api.telegram.org` for the bot whose token you saved in Settings → Integrations, and sends each answer to a Telegram-started message back through the same API, so that text passes through Telegram's servers. Only Telegram user ids in `telegram.allowedUsers` reach the chat; everyone else is ignored. With nobody allowed, a `/start` shows an Allow / Deny bubble on the Mac, and only the first user can be paired that way. An allowed user can start turns in the chat that is open on the Mac, so treat their account like your own. A turn started from Telegram follows the same approval rules as one typed on the Mac. With Auto on, an allowed Telegram user can run non-destructive commands, file edits and MCP tools without anyone approving them, so keep `telegram.allowedUsers` short. Destructive commands still ask, and the card goes to Telegram as Approve / Reject buttons as well as to the Mac. With Auto off, edits, deletions and shell commands ask as usual. Reads, searches and read-only tools run without a card. Files an allowed user sends are saved under `~/.ironpet/telegram/files/` (up to 20 MB each) and handed to the agent, and voice messages go to the transcription server from Settings → Voice. An allowed user can also approve or reject tool approvals of a turn they started, from Telegram. The token is in the Keychain item `ironpet.telegram`, never in `~/.ironpet`.
- **Tasks.** The chat agent and any program that can read `~/.ironpet/token` (the `IronPet tasks` CLI) can create, change and delete tasks through the local server. Tasks are data in `ironpet.db` and never run anything, so the tools need no approval card, like memory-note edits. An automation `prompt` action runs in your chat with the chat's full tools, so it can change tasks and files like anything you type there. An agent that creates or changes one needs your Approve first. A prompt that uses poll item data (`{{item.*}}`) never goes to the chat, because that text comes from outside. It runs in a background agent that gets no MCP tools and cannot change tasks, like the one for meeting summaries. Meeting action items come from what people said on a call, so they are only suggestions until you press Add, and they are never sent to an agent as instructions. The same goes for a watcher automation's `suggest_task` action: text from an email, a chat message or an issue only becomes a suggestion, with control characters removed, length limits, at most 10 per run and only an http or https link, and it becomes a task only when you press Add. The agent is told that task text is data.
- **No API keys.** Chat goes through the sign-in your agent already has. If an agent says it needs you to sign in, ironpet shows a button: for an agent that signs in over ACP it calls `authenticate`, and for a terminal sign-in it opens Terminal with the command the agent gave. ironpet sends nothing anywhere itself, except the optional GitHub and Sentry polling below, voice notes if you turn them on, and the Bun download above.

## What ironpet reads

- `~/.config/gh/hosts.yml` and the `gh` CLI, only with GitHub alerts on (off by default).
- `~/.ironpet/sentry.json` and its Keychain token, only after you've configured Sentry.
- Cursor's `storage.json` and iTerm2 via AppleScript, to find the project you're working in.
- The microphone, only while you record a voice note with voice notes on (off by default). macOS asks for permission the first time you record, not before.
- The microphone and one app's audio (or all system audio, through ScreenCaptureKit), only while a meeting transcript is recording, with meeting transcripts on (off by default). macOS asks for microphone and Screen & System Audio Recording access the first time you start one.
- Wispr Flow's local database, to pick up dictation while the chat is open.
- The general pasteboard, briefly, after you select text in a chat message and release the mouse. ironpet sends the same copy command as Cmd-C to read the selection for the "Ask about this" button, then puts your earlier pasteboard contents back. It never reads the pasteboard otherwise, and the selected text stays in the chat unless you send it.

## Data in `~/.ironpet`

| Path | Contents |
| --- | --- |
| `config.json` | Your settings |
| `threads/` | Saved chats (agent, ACP session id, folder and the visible transcript) |
| `runtime/` | Bun, only if you allowed the download |
| `memory/` | Markdown notes Ghost keeps about you and your projects (you can edit them) |
| `screenshots/` | Screen captures you attached to chats, and `attachments/` with files you attached. Text pasted into the chat over 4,000 characters or 60 lines (both adjustable in Settings > General) is saved there as `pasted-text.txt` and attached instead of staying in the input. A draft over 64 KB is handled the same way |
| `scratch/` | Working folder for chats that aren't about a project |
| `meetings/` | One folder per meeting transcript: the recorded audio as WAV chunks, `transcript.md`, `summary.md`. Kept until you delete them |
| `ironpet.db` | Automation state and logs, usage numbers, and your tasks: titles, notes, links, history, and suggestions from meetings and watchers. Done tasks are deleted after `tasks.keepDoneDays` (30 by default) |
| `token`, `port` | Local server credentials |

The chat that was open when the app quit is reopened on launch. Its id, its Auto switch, your unsent draft and the paths of attached screenshots are kept in the app's preferences (`dev.ironpet.app`), which `uninstall.sh` deletes.

Delete the folder to erase all of it, or run `./scripts/uninstall.sh` to remove ironpet completely (hooks, login item, app, Keychain item, and optionally this folder).

## Screen capture reads other apps and can send text to your agent

Screen capture is off by default. Turning it on in Settings asks macOS for Accessibility access, and for Screen Recording only when a rule needs to read a chat header with OCR.

- **What is read.** The text of the focused window through Accessibility, and at most two small regions (160 pt or less) of the frontmost app through on-device OCR. The screenshot is discarded after OCR. Secure fields, password managers and other denylisted apps, private browser windows, non-web URLs and the locked screen are skipped in Swift code that no rule can override. Private-window detection looks at window titles, so a window with an unusual title can slip through. Secret-looking URL parameters are removed from the item's URL and thread key.
- **Redaction.** Before anything is stored, rules replace secrets in the text with `[redacted:<kind>]`: provider keys and tokens (AWS, GitHub, GitLab, Anthropic and other `sk-` keys, Stripe, Slack, Google, npm, SendGrid), JWTs, private key blocks, `user:password@` in URLs and secret URL parameters, `password=`, `token:` and `.env`-style assignments, card and bank numbers, and long random strings. These rules are patterns, so a secret in a form they do not know passes through them. The local model scores the redacted text and is the second line: an item it still flags stays on the Mac. The rules run again over everything just before it is sent.
- **Where it is stored.** In the `capture_*` tables of `~/.ironpet/ironpet.db`, with the file and its WAL files set to mode `0600`. The text is redacted and not encrypted. The unredacted text of an item that had a secret is kept in `capture_originals` for 24 hours so you can look at what was redacted (Show captures → Reveal original), and is then overwritten and deleted. It is never sent. The database runs with `secure_delete` on, so freed pages are zeroed. A purge and Delete all captures also empty the write-ahead log with a checkpoint, which is best effort (it does nothing while a reader holds the log). The disk itself may keep older blocks, so "deleted" means removed from the database and its log, not wiped from the disk. Items older than the retention setting (30 days by default) are deleted. Settings has a Delete all captures button.
- **What is checked locally.** A model on `localhost` or `127.0.0.1` that you configure scores the redacted text for secrets and decides which items matter. With no reachable local model, nothing is sent. An item still flagged after redaction is kept on this Mac and loses its stored text (the unredacted text stays for the 24 hours).
- **What is sent.** Only items from apps you added to the send list, after the quiet period, to the agent and model you picked for Screen capture. The agent runs in `~/.ironpet/capture/agent` with every permission request denied, except a lookup with `tasks_list` or `tasks_get`. Each send is logged in Settings with the time, agent, model, item ids, byte count and what was redacted (for example `redacted 2 spans (aws-key 1, secret-assignment 1), sent`). The agent's own provider receives that text.
- **What the agent can do.** The captures include text other people wrote, such as Slack messages, so the agent treats them as data and its prompt says so. A message that tries to steer it can still skew its answer, but the agent has no way to act on it. Its only tools are `tasks_list` and `tasks_get`, which read your tasks, so it can look up what exists and what was just finished. It runs through a separate read-only MCP endpoint (`/mcp/tasks-readonly`) that refuses `tasks_create`, `tasks_update`, `tasks_close`, `tasks_delete` and every automation tool on the server, and ironpet refuses every other permission request it receives (files, shell, network). For the Claude adapter ironpet also asks the agent to leave out its shell, edit, web and subagent tools. An agent that runs a tool without asking is outside what ironpet can stop (see the approvals note above), so the guarantee for other agents is the permission refusals and the read-only endpoint. The worst outcome of an injected message is a wrong suggestion. Nothing changes your tasks until you click Add on a suggestion. The tasks you have, including done ones, are visible to the agent's provider when it looks them up.
- **Rules.** Capture rules are JavaScript files that run in a sandboxed QuickJS with a memory limit and a time limit. Files in `~/.ironpet/capture/rules` replace the bundled ones of the same name.

## Voice notes send audio to a server you choose

With voice notes on (Settings → Voice, off by default), each recording is uploaded as a WAV file to the base URL you set, along with the model name and, if you saved one, an `Authorization: Bearer` header carrying your API key. That may be a service such as OpenAI or Groq, or a server on your own Mac. ironpet does not choose the server or fall back to another. While the feature is off, the microphone is never opened and nothing is sent, apart from the one-second test tone that the Test connection button uploads when you press it. The key lives in the Keychain item `ironpet.voice` and is never written to `~/.ironpet`. Recordings are held in memory only: the last one is kept until its transcription succeeds, so Retry can send it again, and none is written to disk. A plain `http://` base URL sends audio and the key unencrypted, so use it only for `localhost`.

## Meeting transcripts record other people

With meeting transcripts on (Settings → Meetings, off by default), starting a meeting records two tracks until you stop: your microphone ("Me") and the audio of the app you picked, or all system audio ("Them"). ironpet's own sound is excluded. Both are written as 16 kHz mono WAV chunks to `~/.ironpet/meetings/<date-time>/` and stay there after the meeting. They are your recording, so ironpet never deletes them; remove the folder when you no longer need it. At most one chunk (up to 5 minutes per track) is held in memory at a time.

- **Audio goes to the configured server.** Every chunk is uploaded to the base URL under Settings → Voice, with the model name and your API key if you saved one. A plain `http://` URL sends it unencrypted, so use it only for `localhost`. Chunks that fail are retried against the same server.
- **The transcript goes to the chosen agent.** When a meeting ends and "Summarize automatically" is on, the full text of `transcript.md` is sent to the agent set as the summary agent (an ACP agent such as Claude Code or Cursor), and from there to that agent's model provider. Turn the setting off and no agent runs.
- **The summary agent cannot change anything.** It runs over ACP in the meeting folder only (ironpet's memory and screenshot folders are not shared), and ironpet answers every `session/request_permission` from it with a refusal, so it cannot edit files or run commands. ironpet itself writes `summary.md` from the agent's text answer. The agent can still read files inside the meeting folder.
- **Regenerate sends the same data again.** Regenerating a meeting sends its saved audio to the transcription server and the new transcript to the summary agent, the same two destinations as the meeting itself, and only when you press the button. It writes `transcript.prev.md`, `summary.prev.md` and short-lived `*.new.md` files inside the meeting folder.
- **Consent.** Recording people without their consent is illegal in many places (for example §201 StGB in Germany). The first meeting shows a notice, the picker repeats it, and the recording status shows in the pet's bubble. You can close that bubble, but the pet then shows a red Recording button for as long as ironpet records, and clicking it brings the bubble back.
- **Permissions are asked late.** Microphone and Screen & System Audio Recording access are requested when you press Start recording for the first time, never at launch and never with the feature off.
- **Voiceprints (off by default).** With "Recognise speakers in meetings" on, ironpet computes a voice embedding for each speaker of the Them track on this Mac. Nothing is sent anywhere for this. After you name a voice, a 256 number centroid, the name, seconds of speech and a meeting count are kept in `~/Library/Application Support/IronPet/voices.enc`, encrypted with AES-GCM under a key in the Keychain item `ironpet.voiceprints`. It is biometric data about people who have not consented, so tell them. Settings has **Forget this voice** and **Forget all voices**, which delete the entries from the file at once. The first time you turn it on, the models (about 21 MB) are downloaded from Hugging Face by FluidAudio.
- **Quitting.** Quitting ironpet during a meeting writes the audio captured so far and what is already transcribed. Chunks not yet transcribed are marked as such in `transcript.md`.
